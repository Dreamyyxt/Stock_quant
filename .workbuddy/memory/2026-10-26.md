## A 股模拟交易可行性验证

**背景**：用户问 A 股盘中能否模拟交易。

**实测结论**
- **老虎模拟盘不能交易 A 股**。`tigeropen` 有 `Market.CN` 常量、A 股日线可取
  （`get_bars(["600519"])` 返回正常，注意符号不带 `.SH` 后缀，`600519.SH` 返回 0 行），
  但 A 股交易只能走沪深港通，属真实账户权限（50 万门槛），模拟盘无此路径。
  账户 segment 仅 S / C，无 A 股交易段。
  `QuoteClient.get_bars()` **没有 `market` 参数**（传了报 TypeError），靠符号识别市场。
- **行情源已解决**：装了官方 `westock` CLI（`~/.local/bin/westock`，v0.0.4，SHA256 校验通过）。
  - `westock kline sh600519 --period m1 --limit N` → A 股 1 分钟线，实时（盘中取到 10:51 bar）
  - 周期合法值：`m1 m5 m15 m30 m60 m120 day week month season year`（**不是 `1m`**）
  - `westock quote sh600519` → 含 `price_ceiling` / `price_floor` 涨跌停价、`volume_ratio`、
    `avg_price`(VWAP)、`turnover_rate` —— A 股撮合规则需要的字段直接就有
  - ETF（sh510300）、可转债（sh113052 / sz128136 / sh111000）分钟线同样可取
  - 已死券返回「未找到行情数据」，需先过滤

**三个会让现有策略直接失效的 A 股规则**
1. **T+1**：个股当日买入不能当日卖出 → 现有 ORB（10:30 入场 / 15:58 平仓）在 A 股个股上
   **规则上不可执行**。只有 T+0 品种能日内：可转债、跨境 ETF、债券/商品 ETF。
2. **成本高一个量级**：个股双边 ≈ 0.102%（佣金万2.5×2 + 印花税0.05%卖出 + 过户费0.001%×2）；
   ETF 免印花税免过户费 ≈ 0.01–0.05%；可转债 ≈ 0.01–0.04%。
   对照 TSLA 实测单笔净 +18.5bp → A 股个股光成本就吃掉 55% 以上。
3. **整手 100 股**（科创板 200 股起）+ **涨跌停**（主板 ±10%、双创 ±20%、ST ±5%、北交所 ±30%），
   涨跌停板上无法成交，撮合必须拒单。

**待决**：走哪条路（QMT/Ptrade 券商柜台 / 云平台模拟 / 自建本地撮合），
以及标的类型（T+0 的 ETF、可转债，还是个股隔日）。

## A 股单标的因子验证（510300 沪深300ETF）——结论：不可交易

**用户选择**：先做因子验证 + 单标的（沪深300ETF 510300）。

**数据现实（决定了只能走日频）**
- westock 分钟线：**仅近 1 个月**，单次跨度 ≤10 天，频控约 20 秒/次 → 日内因子验证样本不足
- 日线：2000 根 / 8.2 年（2018-07-24 → 2026-10-23），qfq，无停牌、无零成交量
- A 股 T+1 + 个股双边成本 ~10.2bp → 日内高频在 A 股两头堵死

**筛选设计（`scripts/ashare_factor_lab.py`）**
- 21 类因子族 × 5 个 horizon = 105 检验
- 分位数用**扩张窗口**（min 250），不用全样本分位，避免泄露分布
- 前瞻收益 = 次日开盘 → 第 H 日开盘（不含信号 bar）
- 块置换零假设（保留自相关）+ BH-FDR + **随机入场时点对照**
- **A 股只能做多 → 取 top/bottom 中可交易的一边**。只按“买赢家”排序会把所有反转因子判死
  （`mom_60d` 20 日：赢家 +0.1bp、输家 +154bp，IC=-0.135）
- 最后 20%（2025-03-03 起）封存

**结果**
- 唯一存活：`mom_5d` / H=10 / 买底部 20% → 样本内 +155.9bp（净 145.9）、
  朴素 t=4.12、重叠调整 t=1.30、置换 p=0.007、随机对照 155.9 vs 26.4bp **p=0.000**
- **但封存段只剩 +19.5bp**（48 个信号日，命中 58.3%）

**落地回测（`rev5_510300_backtest.py`）**
- 策略 **-0.44%**（年化 -0.06%、MDD -24.98%、Sharpe -0.01、72 笔、胜率 51.4%、持仓 41.3%）
- 买入持有 **+32.80%**（MDD -44.75%、Sharpe 0.20）→ 落后 33.24pp
- 封存段 -6.25% vs 买入持有 +10.82%

**三个关键发现（按重要性）**
1. **重叠样本把因子收益放大约 10 倍**：底部 20% 有 264 个信号日，成簇出现、共享同一段反弹；
   实际可交易只有 72 笔，且进的是下跌开始那天而非底部。按真实入场日重算毛收益仅 **14.5bp**。
   → 「信号日平均前瞻收益」≠「策略能拿到的收益」。
2. **参数面是噪声不是平台**：持有 5 天 +80.46%、10 天 **-0.44%**、20 天 +39.57%。
   **被统计检验认证的 10 天设置恰好是九种组合里最差的一个。**
3. 修一处差一错误（`held >= max_hold` 会让实际持有 11 天而非 10 天）后，
   结果从 +22.93% 翻到 -0.44% —— 这个幅度本身就是“没有边际”的证据。

**对抗式审查修掉的 5 个 bug**
1. 自定义 metric_table 被 `defaults` 过滤器捞回再追加 → 仪表盘表格重复
2. 随机对照用日期与 RangeIndex 求交集 → 永远为空，控制组静默失效（最危险：看起来像通过了）
3. 持有期差一错误（11 天 vs 验证的 10 天）
4. 只按 top 分位排序 → 反转因子全被判死
5. 年收益用“当年首根”作基期，漏掉跨年变动，链乘差 2.4pp

**工具**：`scripts/prep_ashare_data.py`（md→csv + 审计）、`scripts/ashare_factor_lab.py`（筛选）、
`rev5_510300_backtest.py`（交付回测）。

### 三个关键语义（这轮最重要的产出）
1. **`clean = statement_ok AND not diffs`**。少了 `statement_ok`，"取数失败"会被算成
   "零差异" —— 两者在净值上看起来一样，在风险上完全相反。这是本模块最危险的一行。
2. **对账与开关耦合**：`EodService.run()` 立刻 `gate.set_reconciliation()`。
   不干净 → 已武装账户立刻被拦；恢复 → 自动恢复（不必重新武装）。
   `LiveGate` 的对账状态**默认不干净**（查不到当 False）。
3. **归因五项之和 = 净收益是恒等式，证明不了什么**（fx 是残差）。
   真正抓错的是两条独立校验：单币种下 fx 必须精确为 0；fee 必须 ≤ 0。

## A 股横截面研究：数据重建 + 稳健性审计（下午）

### 数据层（scripts/fetch_ashare_universe.py）

4. **停牌行 open=high=low=0**：等于在 0 元成交。修法：补成收盘价 + volume=NaN，让引擎的 isfinite 挡掉。

## B5 · 多场所接入（T-501a/b ~ T-504）

### 为什么先建抽象再接 CCXT
没有直接 import ccxt，而是 `gateway.py`（场所无关协议）→ `venues.py`（能力与准入）
→ `ccxt_gateway.py`（翻译，transport 注入）。好处：自测完全离线跑；交易所 SDK 改字段/改异常
名被挡在 transport 边界；接非 CCXT 场所只要实现 7 个方法。`ccxt` 只在
`build_ccxt_transport()` 里延迟导入，缺依赖时给可照做的报错而不是静默降级成假网关。

### 核心设计：ambiguous 是语义不是标签
`GatewayError.ambiguous` 决定「上层能不能重发」。超时/限流/**未分类异常** = True（只查不重发）；
场所拒绝/鉴权失败/能力不足 = False。`submit_with_reconcile` 的 `place_calls` 恒为 1 或 0。
`UNKNOWN` 是合法终态，不是待重试态。理由：成本不对称——多查一次几毫秒，重发一次双倍仓位。

### 准入的关键洞察：能发单号 ≠ 能救回来
必须同时满足 `supports_client_order_id` 和 `supports_query_by_client_id`。
只有前者 = 「看起来有幂等键、实际超时后永远查不清」。这是 B5 最重要的一条。

### 写测试时抓到的真漏洞
`admit()` 原本只查 `default_rules`，漏了按标的覆盖的 `symbol_rules`。
交易所最小名义是按标的定的（默认 5 USDT、BTC 要 100），于是形成「假接通」：
准入通过、监控全绿、每单被最小额拒。改成逐标的检查并指认最差标的。

### 资金费三口径（都做成断言）
1. 符号：CCXT `amount` 是现金流方向（付出为负），账本 `post_funding` 是费用方向（支出为正），**必须取反**。反了的话总额还对得上（两处同反），但归因 funding 方向相反。
2. 计提 ≠ 已结算：`FundingAccrual` 只进展示，账本只记 `FundingPayment`。
3. 幂等键 = `(场所, 标的, 结算边界)`；修正结算只补差额（6→6.5 记 0.5，ref 加 `#amend`）。

### 调度三规矩
逐 lane 捕获 `BaseException`（SystemExit 也不许带走兄弟 lane）；休市期间 `_next_due`
推到 now+interval 所以开盘只跑一次不补跑；`boundaries_crossed` 补资金费账。
`load_tz()` 取不到时区**报错而非退化成 UTC**（退化会在纽约凌晨 4:30 开盘且日志全绿）。

### 三条主线

### 最重要的一条发现（写进 README 不变量第 16 条）
**同一标的下「各自算再相加」与净额算法数值完全相同**（风险对同一标的线性）。
所以只用单标的场景永远测不出重复计算 —— 它只在跨标的、相关时暴露
（朴素相加 130,000 vs 真实 112,694）。测试用例必须用相关标的。

### 灰度路由三条反直觉规则
- **不重新归一化**：某版本本轮没发意图，份额不补给另一个。补了等于灰度版承担全额风险
  而报表仍写「10%」。
- **reduce_only 不缩放**：缩放清仓 = 只清 10%，方向反了。同策略同标的只留幅度最大一份。
- **退役 vs 没见过要分开**：回滚后残留进程还在发意图 → 丢弃记账（不能抛错，
  否则一个忘杀的进程让整轮路由中断、所有策略停摆）；从没登记过的版本才抛。

### ERC 的注释错了（已修）
常数相关矩阵下 `1/σ` **恰好等于**等风险解（可证）。真正失效的是**块相关**：
A/B ρ=0.95、C ρ=0.1 时，1/σ 给 38.7/38.7/22.6 的风险占比，ERC 给 33.3 三等分，
组合波动 383,695 → 373,558。文档与验收场景都改成块相关。

### 顺序 bug：校验必须在状态判断之前
`auto_adjust` 原本先判 `state != CANARY` 就 return，导致「已回滚 + 判定值拼错」
被静默放过 —— 一个错字让自动化悄悄失效。改成先校验 verdict 再判状态；
非灰度状态改为幂等空操作（自动化按周期调用，抛错只会制造假告警）。

### 权限划分（贯穿全项目的一条原则）
