# B12 · 回测引擎

> 验收：**15/15 套件、1788 条断言**通过（B12 新增 161 条）
> 「这套策略赚不赚钱」第一次有了平台内答案 —— 而且用的是**同一套账本、同一个成本模型、同一个回放器**

## 这一批解决的是哪道墙

B11 之后，系统能算账、能风控、能下单、能对账，但**没有任何证据说明这套参数会不会赚钱**。
答案一直躺在 `research/ashare_ew20/` 里 —— 那是另一个世界：

- 它自己读 CSV，自己算成本，自己记持仓，自己算指标；
- 它和平台唯一的共同点是「都用 A 股日线」；
- 所以平台上的风控、成本模型、整手规则、涨跌停，在它的结论里**一次都没出现过**。

这一批要消掉的不是「缺一段回测代码」，而是**两个账本**。

```
BarPanel ──┐
           ├─ 事件流（market_snapshot / strategy_intent / cycle / fill / order_ack / order_cancel）
策略 compute ┘        │
                      ▼
                 Replayer（B1，实盘同一个） ──→ Ledger / RiskEngine / MarketDataBook / CostModel
```

一句话：**回测不记账，回测只生产事件。**

## 三条结构性的保证（不是声明，是代码结构）

1. **无未来函数靠执行顺序**：`_settle(i)`（读当天**开盘**）严格先于 `_signals(i)`
   （读当天**收盘**）。K 段用 `ast` 扫源码把这条顺序钉住 —— 改顺序就是引入未来函数。
2. **每日估值必须走面板，不能走行情表**。行情快照只在调仓日发，拿它估值会让 NAV
   变成 20 天一级的阶梯：波动率被压小、回撤被削平、夏普虚高。这类错误不报错，
   只产出漂亮的假数字。
3. **策略只看得到窗口内的 bar**，停牌股直接不给 —— 否则策略会对永远成交不了的
   标的反复下单，白占在途额度。

## 硬证据：全池回测 + 与手工基线对账

```
区间        2019-01-18 → 2026-10-26   1880 个交易日 / 7.770 年   794 只
期初 → 期末 10000000.00 → 43993671.45
年化        21.01%          年化波动  23.15%
夏普/索提诺 0.975 / 1.382   最大回撤  -33.85%（2026-06-03 → 2026-10-22）
成本        17.637 bps/平均NAV        平均敞口  98.36%
成交笔数    3644 笔          归因闭合  ✅ 六项之和等于净收益
```

`check` 子命令**独立重算**（现金从账本取、持仓从账本取、价格从面板取，三处都不过
引擎的 `nav()`）：

```
NAV（引擎）      27934107.87
现金 + 持仓市值   27934107.87   （现金 749998.78 + 持仓 27184109.09，179 只）
差额              0.0000   → ✅ 恒等
```

与手工基线（`research/ashare_ew20`，不复权、开盘成交、全摩擦）：

| 指标 | 平台 | 研究 | 差 |
|---|---|---|---|
| 年化 % | 21.010 | 18.780 | **+2.230** |
| 最大回撤 % | -33.850 | -26.100 | -7.750 |
| 夏普 | 0.975 | 0.974 | +0.001 |

年化差 +2.23pp 被逐条归因到六条**结构差异**（后复权 / 滑点记账 / 净额取整 /

「单位风险收益」是一致的 —— 差异来自口径，不来自算术。

## 修掉三个真 bug（前两个在实盘代码里）

1. **部分成交时，策略归属按下单量记**（`replay._on_fill`）
   `intent.attribution` 是按整单量切好的，直接传给一笔较小的成交，`attr_qty` 就
   超过真实持仓。后果链：策略敞口虚高 → 净额算出的卖单比持仓大 1% → 风控判它
   「穿过零轴开空单」拒掉 → **组合只进不出**，报告上只表现为「换手不高」。
   修法：`_rescale_attribution()` 按 `filled/ordered` 等比缩放，尾差补到最大一笔。
2. **风控用的 NAV 是昨天**（`backtest.run`）
   原来是 `_signals` → `_nav`。一笔「把持仓卖光」的卖单会被算成「单笔占 NAV 101%」
   被拒。修法：决策发生在今天收盘，就先按今天收盘价估值再进决策轮。
3. **撤单静默失败**（`backtest._signals`）
   回测从不发 `order_ack`，订单停在 `SUBMITTED`，而迁移表里 `SUBMITTED → CANCELLED`
   不合法 → 撤单被吞，同一张单每天重试一次，把 `lot_too_small` 刷成 **2592 次**。
   修法：补发 `order_ack`；`_cancel` 核对 `state is CANCELLED`。

顺带修掉的**契约缺口**：策略无法表达平仓。`SignalOut(suggested_weight=0)` 原被
`adapt_signals` 当作「没有意见」丢弃 → 组合只加仓、永不退出。现在**显式 0 是平仓指令**，
裸 0（字段缺省）才是「没有意见」。

## 顺手改掉的两个「假数字」

1. **成交笔数报 `len(trades)`**：明细有显示上限，全池回测把 3644 笔说成 400 笔。
2. **整手零头被记成"部分成交"**：等权组合每天每只股票的零头都记一条 `partial`，
   全池 2371 条，把真正的资金约束（`cash_short`）淹掉。现在拆成
   `partial`（真缩量）与 `lot_rounding`（整手取整的零头）。

## 五条日线上的诚实边界

1. **不模拟限价排队**：信号日收盘出单 → 次日开盘价 + 滑点成交。真实排队可能整天不成交。
2. **涨跌停用容差 0.2% 判板**（复权与四舍五入的余量），贴板的真实可成交性更差。
3. **不模拟盘中路径**：日线只有 OHLC，日内触发止损/加仓的顺序无法还原。
4. **停牌用「最近一次收盘」估值**：行业惯例，但那几天的 NAV 是估的，不是成交出来的。
5. **`xshg` 未通过实盘结构准入**（声明「无法按客户端订单号回查」）。回测只借它的
   规则矩阵，**不代表 A 股已可上线** —— 报告的口径说明里每次都写这句。
