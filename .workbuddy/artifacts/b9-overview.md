## 四个关键决策

1. **日历从真实行情反推，不手抄节假日。**
   510300 日线 1999 个交易日 → 155 个休市日，2026 年那 19 天与法定安排逐条吻合。
   手抄表抄错一天全错，而且**错了没人会发现**；数据反推不会。

2. **周期从固定锚点算，不从"上次运行"算。**
   `next = last_run + N` 一次晚跑就永久偏移，一年后回测的"20 日"和实盘的"20 日"
   错开十几个交易日，而两边都觉得自己对。`anchor + k×N` 让漏跑只等于少跑一次。

3. **跑之前先落 claim。**
   进程可能在下单之后、落盘之前被 kill。这时重跑=重复下单，不重跑=漏一次调仓。
   `claim → run → complete` 三段 + `PreflightAbort` 区分「确定没跑」和「不知道跑没跑」，
   后者保留 claim、拒绝自动重跑、要求人工 `resolve()`。

4. **收盘 + 结算延迟之前不算当日。**
   14:00 拿到的价格也叫 close，但它不是 15:00 那个。回测与实盘的差异就藏在这里。

## 验证到什么程度

- 真实 A 股 2026-06-01 / 2026-06-30 连跑两拍，第二拍基于第一拍持仓算差额；
- 同一数据日再 tick → `skipped_already_ran`，成交笔数不变；
- 规则日历误差方向与量级可量化（年均 17.2 天，单向，漏判必须为 0）；
- 页面两种红状态（`--fault sched-in-doubt` / `sched-stale-calendar`）都截过图，
  500px 窄屏无横向溢出；
- 页面探针在健康 / in_doubt / 缺端点三种 fixture 下全绿。

## 明确没做的（下一批要接的）

1. **账本仍不持久化** —— 独立进程跑两次 = 第二次从空仓建仓。这是 B10 第一件事。
2. **调度器不自己定时** —— 需要 cron/systemd 驱动 `tick()`。
3. **Crypto 24/7 排期未接** —— `scheduler.py` 的多 lane 已有，`RebalanceSpec` 目前只按 A 股日历判。
4. **`resolve` 没有审计落库** —— 结论写回了状态文件，但没进 `AuditLog`。
