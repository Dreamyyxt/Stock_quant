# 日内交易引擎（模拟盘验证阶段）

> 目标：**先在老虎模拟盘把日内策略真实跑起来，用数据判断它值不值得上实盘。**
> 不是"先做个能下单的机器人"，而是"先造一个能证伪自己的实验装置"。

| 项 | 状态 | 说明 |
|---|---|---|
| 引擎链路（信号→下单→平仓→统计） | ✅ 跑通 | 合成的完整交易日 390 根 K 线，32 笔成交，收盘前全部平掉 |
| 风控硬约束 | ✅ 验证生效 | 单日亏损熔断、单日笔数上限、单票来回上限、冷却期、强制平仓均按预期触发 |

## 1. 架构

```
行情 Provider  →  日内信号  →  交易引擎  →  执行适配器
(tiger/alpaca/     (动量/RSI/     (仓位/风控/    (模拟撮合 or
 yfinance/replay)   VWAP/量比)     当日平仓)      券商委托)
```

四个部件都可以单独替换，所以"回放结果"和"模拟盘结果"来自**同一份策略代码**，
唯一变化的是数据源和撮合方式。这一点很重要：如果回放和实盘跑的是两套逻辑，
回放就只是自我安慰。

| 文件 | 职责 |
|---|---|
| `intraday/providers.py` | 分钟级行情，含权限探测与历史回放 |
| `intraday/signals.py` | 因子压缩到分钟级，输出可解释的入场/出场理由 |
| `intraday/execution.py` | 模拟撮合 / 券商委托，统一接口 |
| `intraday/engine.py` | 会话主循环、仓位、风控、当日平仓、统计 |

## 2. 三种运行方式

### 2.1 离线自测（不需要网络、不需要券商）

```bash
.venv/bin/python main.py --mode intraday-test --cash 100000
```

用确定性随机游走数据跑完整会话，验证的是**链路和风控**，不是策略收益。
每次改动引擎后都应该先跑这个。

### 2.2 历史回放（验证策略）

```bash
.venv/bin/python main.py --mode intraday-replay --date 2026-10-23
# 加速（跳过部分分钟，精度下降）
.venv/bin/python main.py --mode intraday-replay --date 2026-10-23 --speed 3
```

- 数据来源：yfinance 1 分钟线，**只能取最近约 7 天**，更早的日期会报错；
- 首次下载后缓存在 `state/intraday_cache/`，同一天重复回放不再联网；
- 撮合方式：参考价 ± 滑点即时成交，不含排队和部分成交，因此回放结果是**乐观上限**。

### 2.3 模拟盘实跑

```bash
# 先看能拿到什么行情
.venv/bin/python main.py --mode probe

# 影子模式：真的取行情、真的算信号，但不发单（只记账）
.venv/bin/python main.py --mode intraday --dry

# 真实下单到模拟盘
.venv/bin/python main.py --mode intraday
```

运行时段自动限制在美东 09:40–15:50，收盘前强制平仓，不会留隔夜。

## 3. 行情源怎么选

`--mode probe` 会打印实际能力，判读方法：

| 输出 | 含义 | 能否做日内 |
|---|---|---|
| `tiger_1min.ok=true`，`last_bar` 距现在 < 2 分钟 | 有实时/准实时分钟线 | **可以**，首选 |
| `tiger_1min.ok=true`，`last_bar` 落后 15 分钟 | 延迟行情 | 不能，只能回放 |
| `alpaca_1min.ok=true` | IEX 免费实时源 | 可以，但只有约 2-3% 成交量，价格有偏差 |
| `yfinance_1min.ok=true` | 延迟行情，限 7 天 | 只能回放 |

切源方式（`config/.env`）：

```bash
INTRADAY_PROVIDER=alpaca      # auto | tiger | alpaca | yfinance | replay | synthetic
ALPACA_API_KEY=...
ALPACA_API_SECRET=...
ALPACA_FEED=iex
```

**建议**：验证阶段用 Alpaca 免费源，长期开老虎实时行情。理由不是价格好坏，
而是**下单和行情同源**——跨源会出现"按 A 的价格挂单、按 B 的价格成交"，
回放和实盘的偏差会永远说不清楚是谁的问题。

## 4. 策略逻辑（当前版本）

每根 1 分钟 K 线，对每只标的计算：

| 因子 | 定义 | 作用 |
|---|---|---|
| 动量 | 15 分钟收益率，横截面排名 | 主信号，只做多头动量 |
| VWAP 偏离 | `close / session_vwap - 1`，排名 | 确认价格在当日成交密集区之上 |
| RSI(14, 1min) | 标准 Wilder RSI | **只做否决**，超买不追 |
| 相对量能 | 近 5 分钟量 / 近 60 根中位量 | 过滤没量的假突破 |
| ATR% | 近 14 根振幅 | 仅记录，用于后续波动率归一 |

评分 = `0.5 × 动量排名 + 0.3 × VWAP排名 + 0.2 × (1 − 超买惩罚)`

入场需**同时**满足：评分 ≥ 0.72、动量 > 0、价在 VWAP 上、RSI < 76、量比 ≥ 0.8。

出场（任一触发）：跌破止损（-0.8%）、触及目标（+1.8%）、持仓超 90 分钟、
动量转负、RSI ≥ 80、评分跌破 0.35、跌破 VWAP 0.2%。

所有阈值都在 `config/settings.py` 的 `INTRADAY_CONFIG`，**没有任何魔法数字藏在代码里**。

### 风控（硬约束，不可绕过）

- 单票占净值 12%，总敞口上限 45%，最多 3 个持仓
- 单日亏损达 1.5% → 立即清仓 + 当日停止交易
- 单日最多 30 笔，单票最多 3 个来回
- 平仓后同标冷却 25 分钟，避免来回打脸
- 收盘前 15:50 强制平仓

## 5. 怎么判断"策略有没有问题"

跑完一个会话会生成 `logs/intraday_summary_<date>.json` 和
`logs/intraday_trades.jsonl`。**不要看单日收益**，看这四个数：

| 指标 | 及格线 | 说明 |
|---|---|---|
| 成交笔数 | ≥ 20 | 少于 20 笔的样本无法判断 |
| 胜率 | 见下 | **必须和盈亏比一起看**，单独看会误判 |
| 盈亏比 | 平均盈利 / 平均亏损 | 胜率 40% + 盈亏比 2.0 是好策略；胜率 70% + 盈亏比 0.4 是灾难 |
| 最大日内回撤 | < 单日亏损限额的 80% | 频繁逼近熔断说明仓位过大 |

最低验证量：**连续 20 个交易日、累计 ≥ 100 笔成交**，再看夏普式的日收益均值/标准差。

回放结果要打折：回放假设瞬时成交、无排队、无部分成交，
真实滑点通常吃掉 0.02%–0.05% 每笔。日均 5 笔就是每天 0.1%–0.25% 的额外成本。

## 6. 已知限制（必须知道）

1. **延迟行情做不了日内**。如果 `probe` 显示只有延迟数据，那模拟盘跑出来的
   收益曲线没有参考价值，别拿它做上线决策。
2. **PDT 规则**：美股账户 5 个交易日内 ≥ 4 次日内往返会被标记为 Pattern Day Trader，
   需要维持 $25,000 最低权益。模拟盘不受限，**实盘必须先把这条算进去**。
3. **只做多**。空头有借券成本和 locate 风险，验证阶段不做。
4. **回放不含盘口**。用分钟收盘价近似成交，跳空时实际成交会更差。
5. **单账户单进程**。日内引擎与日频调度共用同一把账户锁，不能同时跑；
   要并行必须开独立账户。
6. **没有公司行为处理**。拆股、停牌、财报跳空都需要人工核对。

---

## 7. 上实盘前的门槛

在模拟盘满足以下全部条件，才值得讨论实盘：

- [ ] 连续 20 个交易日有完整会话记录，无异常中断
- [ ] ≥ 100 笔成交，胜率 × 盈亏比 > 0.8
- [ ] 日收益均值为正，且最大单日亏损未触及熔断
- [ ] 回放 vs 模拟盘的成交价偏差可解释（知道差在哪，而不是"大概差不多"）
- [ ] 告警通道验证可用（人为触发一次，确认能收到）
- [ ] 明确 PDT 状态与实盘账户权益
- [ ] 首月实盘资金 ≤ 总资金 5%，且单笔风险 ≤ 账户 0.2%

## 策略 v2：开盘区间突破（2026-10 重做）

原「动量排名 + VWAP + RSI」入场条件经 116 个交易日真实分钟数据检验为**反向预测**：
score 越高，后续 30 分钟越差（0.92–1.01 档为 -0.089%、命中率 37%）。这不是阈值问题，
是方向错了，因此换信号而不是调参。

**新规则（`signal_mode="orb_breakout"`）**

| 环节 | 规则 |
|---|---|
| 区间 | 开盘前 30 分钟（09:30–10:00）的最高价，当日固定不再重算 |
| 入场 | 价格突破区间高点，且相对成交量 ≥1.5x，15 分钟动量 ≥0.5%，且在 VWAP 之上 |
| 入场时间窗 | 10:05 – 13:40（给 2 小时持有留出强平时间） |
| 出场 | **时间出场 120 分钟**为主；止损 2%；动量/VWAP 仅作灾难刹车（-2%） |
| 仓位 | 最多 3 个持仓，每个 12% 净值，总敞口 ≤45% |
| 笔数上限 | 12 笔入场/日（计数口径已修正为「入场数」而非「入场+出场」） |

**为什么是「持满 2 小时」**：同一批信号在 30/60 分钟持有期下净收益为 -441 / -587 ppm，
到 120 分钟才转正（+765 ppm）。价差成本约 250–310 ppm/回合，短持有期内的期望涨幅盖不住它。

**为什么止损放到 2%**：这 8 只票 1 分钟 ATR 约 0.1%，2 小时自然波动约 0.1%×√120 ≈ 1.1%，
原 1% 止损正好落在 1 倍标准差上——173 笔里 30 笔被纯噪音打掉，平均 -1.11%，吃掉全部毛利。

**实测结果（2026-05-15 → 2026-10-23，112 个交易日，SIP 全美行情）**

| 指标 | 值 |
|---|---|
| 累计收益 | +1.16%（10 万 → 10.116 万） |
| 权益峰谷回撤 | **-1.42%** |
| 回合数 | 169（1.5 笔/日） |
| 单笔均值 | +0.058%（t = 0.76） |
| 逐笔命中率 | 46.7% |
| 盈利日 | 41/112 |

**结论：方向对了，但还不构成可上实盘的证据。** 单笔 t 值仅 0.76，且 +1.16% 的收益在
7 月之前是 -1.5% 的浮亏，全部利润来自 7 月后的行情。回撤大于总收益，Calmar < 1。

## 单票策略：TSLA 开盘区间突破（2026-10 研究结论）

从「8 只票分散组合」转向「只做特斯拉」。样本 1,246 个交易日（2021-11-01 → 2026-10-23），
1 分钟 SIP 全美合成行情（488,643 根），成本按实测价差（中位 3.02 bp，半价差 1.51 bp，
往返约 4 bp）。

**筛选过程**

1. 25 个规则族（开盘区间突破各变体、跳空延续/回补、VWAP 回归、首小时动量/反转、
   前日高低点突破、尾盘动量）各跑样本内（前 60%）/样本外（后 40%）。
   只有**早盘开盘区间突破**在两个半样本都稳定为正；VWAP 回归两半都为负（-18.8 / -1.2 bp）。
2. 对该族做 108 组参数网格：**76 组两半皆正**；邻域（5/15/30 分钟区间 × 10:30/11:00/11:30
   截止 × 多/空/双向 × 持到收盘/持 120 分钟）都指向同一结论，不是单点巧合。
3. 止损宽度 81 组网格：**77 组两半皆正**，说明结果不依赖某个特定止损。

**最终规则（`tsla_breakout_backtest.py`，`--rule orb`）**

| 环节 | 规则 |
|---|---|
| 区间 | 09:30–10:00 的最高/最低价，当日固定 |
| 入场 | 10:30 前第一次收在区间外，下一分钟开盘成交；先破哪边做哪边 |
| 止损 | 区间高度 × 2（约 2–4%） |
| 出场 | 收盘前平仓，不留隔夜；每日最多一笔 |
| 仓位 | 100% 净值（`--exposure` 可调） |

**结果（2021-11 → 2026-10，838 笔）**：+279.8%，年化 31.0%，最大回撤 -27.1%，夏普 1.06，
胜率 52.5%，单笔净 +18.5 bp（t = 2.36）。同期买入持有 -2.5%（回撤 -73.6%）。

**稳健性检验**

- 多空两侧都为正：多 418 笔 +0.20%/笔，空 420 笔 +0.17%/笔
- 剔除 2022 崩盘年：+11.8 bp/笔（t = 1.41），edge 不依赖单一年份
- 随机方向零假设（同样入场时点、同样出场与止损，方向随机，200 次）：均值 -1.9 bp，
  95 分位 +10.0 bp，实测 +18.5 bp → p = 0.010
- 剔除最赚 5 笔后仍为 +$169k（占总额 61%），不依赖个别尾部

**复现**

```bash
python scripts/fetch_tsla_sessions.py --symbol TSLA --start 2021-11-01 --end 2026-10-23 --workers 4
python scripts/tsla_cost.py              # 实测价差 → state/tsla_cost.json
python scripts/tsla_lab.py               # 规则族筛查
python scripts/tsla_refine.py            # 参数网格
python scripts/tsla_refine.py --stage2   # 止损宽度敏感性
python scripts/tsla_refine.py --stage4   # 多空拆解 / 剔除年份 / 随机方向零假设
python tsla_breakout_backtest.py         # 正式回测 + 三件套 + 仪表盘
```

## 接进真实引擎：`signal_mode="orb_tsla"`

回测脚本和实盘引擎是两个程序，回测赚 280% 不代表引擎也会。所以这套规则被**移植**进
`intraday/`（不是重写），并用 1,246 个交易日逐个调 `build_engine(mode="replay")` 回放对账。

```bash
python scripts/engine_replay_tsla.py            # 全历史引擎回放 + 对账 + 仪表盘
python scripts/engine_replay_tsla.py --reuse     # 只重出报表，不重跑
python main.py --mode intraday-replay --strategy orb_tsla --date 2026-10-23
python main.py --mode intraday --strategy orb_tsla --dry   # 模拟盘影子运行
```

**对账结果（838 笔全对齐）**

| 指标 | 引擎回放 | 独立回测 | 差异 |
|---|---|---|---|
| 累计收益 | +267.7% | +279.8% | -12.1pp |
| 年化 | 29.9% | 31.0% | -1.1pp |
| 最大回撤 | 28.6% | 27.1% | +1.5pp |
| 夏普 | 1.04 | 1.06 | -0.02 |
| 胜率 | 52.51% | 52.51% | 0 |
| 笔数 / 止损笔数 | 838 / 40 | 838 / 40 | 0 |
| 单笔净 | 18.20bp | 18.50bp | -0.30bp |

逐笔：838/838 笔日期对齐，方向零差异，单笔差中位 0.06bp、p95 0.29bp、最大 92bp。
**收益差的 12 个百分点全部来自那 40 笔止损的成交价**——回测假设正好成交在止损价，
引擎按真实价格成交（跳空穿过止损时更差）。这是目前最需要向实盘预期打折的地方。

**为接这套策略改的引擎能力**

1. **做空**：`Position.side`、`SimExecution` 负持仓、盈亏乘方向、gross 用绝对值。
   空头用 `allow_short` 显式开启，长仓策略不会因为卖多了意外变成空头。
2. **信号自带止损**：`IntradaySignal.stop_distance`（绝对价差）优先于固定百分比止损，
   开盘区间止损才能按"区间高度 × 2"落地。
3. **止损改成盘中判断**：原来只看收盘价，会漏掉盘中刺穿又收回的止损。
   实测 2022-09-21 一笔空单因此从 -209bp 变成 +212bp，方向都反了。
4. **回放不再有一根 K 线的前视**：`ReplayBarProvider.get_recent` 只返回已收盘 K 线，
   `mark_price` 返回当前 K 线开盘价，入场价 = "下一分钟开盘"，与回测一致。
5. **合成行情成交量改为对数正态 + 突发**：原来均匀分布被 5 根均线抹平，
   相对量永远 ~1.0，任何带量能过滤的策略在离线冒烟测试里都不开仓。

**已知差异（有意保留）**

- 回测里的止损价成交是乐观假设，引擎按真实价成交，所以引擎更悲观；
