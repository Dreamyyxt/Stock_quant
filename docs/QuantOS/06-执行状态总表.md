## 3. 本轮核对揪出的三处「文档落后 / 新缺口」

> 这三条是读文档 + 查代码对不上才发现的，`04-未完成清单.md` 里没有或已过时。

### 3.1 `04` 的 2.3 已过时（R-D05 归属不再是「按比例分摊」）

`04` 第 114 行仍写「仍是按比例分摊，不是精确的 strategy → qty 归属」。
实际 B12 修掉「部分成交时归属按下单量记」之后，`ledger._apply_attribution()` 是
**逐笔按实际成交量累加** `attr_qty` / `attr_cost` / `attr_realized`，只有拆股
（`apply_split`）才按比例缩放 —— 那是正确行为。
**真正缺的不是归属，是出口**：`metrics.py` 里没有 `strategy.realized` 一类指标，
所以页面上看不到各策略盈亏。这条要挂到 `R-O01` 而不是 `R-D05`。

### 3.2 新缺口：回测产物不落盘（B12 的成果会蒸发）

`scripts/quantos_backtest.py` 三个子命令的结果**只走 stdout / `--json`**，
没有 report store，也没有生成 `backtest_report_id`。
后果有两个：
- `R-S02` 的「版本绑定回测报告」永远填不上；
- 「回测也上平台」目前止于命令行 —— 终端一关，年化 21.01% 就没有任何可追溯的落点。

**B15（回测上屏）的第一步必须是把回测结果落成带指纹的产物**，否则 `/api/ops/backtest`
只能现场重跑一遍（全池 70 秒，页面等不起），或者继续显示假的演示卡片。

### 3.3 无部署产物（`R-A01` / `R-A05` / `R-A09` 是同一个缺口）

仓库里没有 `Dockerfile`、`docker-compose.yml`、systemd unit、`.github/workflows`。
这三条需求合起来其实只差一件事：**把「进程编排」从 cron 片段升级成可交付的部署单元**。
现在 `quantos_up.py --crontab` 给出的是一段贴进 crontab 的字符串 —— 能跑，
但不是部署，因为它不解决「进程僵死」「换机器」「异地备份」。
