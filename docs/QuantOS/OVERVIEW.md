## 三、三条最重要的设计判断

### 1. 自由度比的分母是待估参数个数，不是标的个数

同一份数据，两种口径给出相反结论：

```
3 标的 / 160 观测
  按标的算：160 / 3   = 53.3    ← 看起来极其充裕
  按参数算：160 / 6   = 26.67   ← 真实自由度（3 个 σ + 3 个 ρ）

5 标的 / 40 观测
  按标的算：40 / 5    = 8.0     ← 看起来还行
  按参数算：40 / 15   = 2.67    ← 实际已经不可信，触发告警
```

这是本批最容易自我欺骗的地方：分母用标的数，任何面板都显得样本充足。
所以页面和指标层都直接写「160 观测 ÷ 6 个待估参数」，让看的人自己复核分母。

### 2. 收缩前后一起给，因为收缩能把结论改掉

```
            样本值     收缩后      Δ
QQQ / SPY   0.866  →  0.622    -0.244   ← 超分辨率
QQQ / TLT  -0.376  → -0.247    +0.129   ← 超分辨率
SPY / TLT  -0.332  → -0.217    +0.115   ← 超分辨率
```

ρ 的分辨率（标准误上界）是 0.0791。三对的相关性被移动的幅度**全部超过统计噪声** ——
也就是说那个 0.622 的主要成分不是「市场相关性」，而是「我们选择了 δ=0.3 往均值拉」。

只显示收缩后的值，等于把这个人为选择说成观测事实。所以：

- `CovarianceEstimate` 额外保留 `raw_corr`，页面永远两个数并排；
- 位移超过 `corr_stderr` 的对标「超分辨率」；
- 落盘（`to_dict`）同样带对比，否则读回来的模型只剩结论、没有「结论怎么来的」。

顺带一条：**n=2 时收缩完全无效**。常数相关目标就是那唯一一对 ρ，收缩只是原地缩放。
这种情况显式告警，而不是让人以为「已经做了稳健处理」。

### 3. 分红不单列，就会被 fx 残差吃掉 —— 而恒等式照样闭合

```
除权日：现金 +1,000，市值 -1,000，net 不变
  分红不入账 → trading 掉 1,000，fx 被算成 +1,000
  报表显示：汇率损益 +1,000   ← 真正的原因（分红）消失了
  归因恒等式：仍然闭合 ✅
```

这是 B4 那条教训的第二次出现：**残差项能吸收任何错误**，闭合证明不了没漏记。
所以对账第五项的严重度刻意排在持仓差异与现金差异**之前** —— 它是根因，
先报现金差异等于让运维去修症状。

拆股同理：只改 `qty` / `attr_qty` / `avg_cost`，**绝不改 `buy_at_decision`**。
50 股 @180 拆成 100 股 @90，`buy_at_decision` 仍是 9,000；改成 18,000 就等于
承认赚了 9,000，而没有任何一笔成交能解释它。

## 四、复权口径：一个往危险方向偏的坑

同一份 A 股数据，两种口径各估一次 σ：

```
sh600000   σ = 24.0%   （400 个交易日，样本期内 340 次除权）
未复权口径的 σ 比前复权高 +2.0%
```

偏差方向很重要：σ 被**低估** → 同样的风险预算能买更多 → 实际敞口超标。
所以 `PriceSeries` 约定 `close` 是前复权价，换算关系 `未复权 = close / adj_factor`。

顺便说明一件事：这段样本里「未复权价格翻几倍」的现象**没有出现**，因为它是分红除权
（2~3%），不是拆股。拿它当拆股例子会得到一个漂亮但不存在的结论 ——
所以验收脚本断言的是「两种口径的 σ 差」，不是「价格差几倍」。

## 五、本轮修掉的问题（都是写测试时才暴露的）

| 问题 | 后果 |
|---|---|
| `dof_ratio` 分母用标的数 | 5 标的 40 观测算出 8.0，看起来宽裕，实际参数有 15 个。同一份数据两种口径给出相反结论 |
| 幂等去重污染派生字段 | 重复回报让 `net_deposits_base` 加两次而现金只加一次 → `net_pnl` 凭空 -100,005，差额被 fx 残差吞掉，**`closes` 依然 True** |
| 分红落进 fx 残差 | 报表显示「汇率损益 +1,000」，真正原因消失 |
| 2 标的时收缩无效却无提示 | 让人以为已做稳健处理 |
| `_weighted_cov` 的 `intersect_dates` 写错 | `set(series[0].points and [...])` 得到空集合，静默退化成 `n_obs=0` |
| `Decimal ** 分数次幂` 不支持 | EWMA 的 λ 走 float（不影响可观测精度，注释写明），年化开方用 `Decimal.sqrt()` |
| `post_interest` 复用 `post_funding` 踩 frozen dataclass | meta 改不动 |
| 演示数据相关系数接近 0（-0.07） | 三个标的看起来互相独立，整套风险预算演示没有意义。注入共同因子后才是 0.62 / -0.25 |
| 归因日报还是五项 | 分红那天页面会显示「未闭合」，而账其实是对的 —— 上屏时才发现的口径漂移 |


起服务后打开 `http://127.0.0.1:8787/` 进「运维」页，三块新内容在「归因日报」下面：

```
风险模型     判定横幅 + 观测数/自由度比/ρ 分辨率/模型年龄
             相关系数「样本值 → 收缩后」+ Δ + 波动率 + 告警原文
策略灰度     每策略 稳定版 → 灰度版、权重百分比条、状态、已退役版本、通道
AI 收件箱    提交编号、AI/人工标记、类型、摘要、提交人、待复核条数
```

三条硬规矩：这个端点请求失败**不计入离线判定**；三块任一拿不到数据就显示
「看不到」并说原因；`LIVE.on === false` 时降级为「需要连接运维服务」——
**绝不编一个「σ 健康」的绿灯**。

## 七、六条已知限制（不藏）

1. **估计只解决「给定假设怎么摊」，不解决「假设会不会变」。** 模型 > 30 天判不可信，
   但 30 天这个阈值是拍的 —— 没有依据说 29 天一定安全。滚动重估与 ρ 敏感性未做。
2. **协方差参数个数是 O(n²)。** n 标的要估 `n + n(n-1)/2` 个参数：794 只 A 股需要
   315,271 个参数，而观测数只有 O(T)。实际只能压到几十只，或改用因子模型（未实现）。
3. **公司行动只覆盖分红 / 拆股 / 融资利息。** 权证行权、并购换股、供股、借券费没纳入。
   声明里出现未知类型会报「未知公司行动」，但那只是报出来，不会自动处理。
4. **分红税按账单倒推，不按税务规则算。** 美股 30% / 爱尔兰 15% / 港股各不相同的
   预扣逻辑没有建模；账单拆错，账本就跟着错。
5. **灰度仍只到版本级，`CanaryRouter` 仍是纯内存。** 两条都是从 B6 原样留下来的。
   页面上能看到灰度状态，但那份状态活不过一次进程重启。
6. **页面探针是 DOM 桩，不是真浏览器。** 能抓数字漂移和漏字段，抓不到 CSS 布局问题。
   布局另用 headless Chrome 截图人工核对（1440 / 500 两个宽度）；Chrome headless
   的窗口宽度下限是 500px，390px 真机宽度靠命令行验证不了。
